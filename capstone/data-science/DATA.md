# Data Decision

The Week 11 dataset is synthetic incident data for the Harborlight Logistics Support Desk staffing question. It is generated by capstone/data-science/scripts/generate_data.py with a fixed random seed so another student can reproduce the same file.

## Why synthetic data is needed

The existing incident data described in the track does not include a category for every row or a resolution time for closed rows. The staffing question cannot be answered well without those fields. A uniform random dataset would also hide the patterns Dana needs to see, so the generator plants realistic structure and documents it here.

## Columns

The generated file is capstone/data-science/data/generated_incidents.csv.

Columns are incident_id, title, description, category, status, created_at, resolved_at, resolution_hours, source_system, and synthetic.

Every row has a category. Every closed row has resolved_at and resolution_hours. Open and in progress rows leave resolved_at and resolution_hours blank.

## Categories planted in the data

Categories are scanners and handhelds, dispatch app, printers and labels, logins and access, network, and warehouse systems.

Each category has its own title list and its own typical resolution time. Titles hint at the category but do not always name it directly.

## Time pattern planted in the data

The dataset covers 180 days. Incident volume grows slowly across the period. Weekdays have more incidents than weekends. Working hours have more incidents than overnight hours.

Resolution time uses a skewed lognormal shape. Most incidents close in hours. A smaller number take days. This matches the track guidance to compare medians and 90th percentiles instead of relying only on averages.

## Status pattern planted in the data

Older incidents are mostly closed. Recent incidents are more likely to be open or in progress. If a generated resolution time would end after the dataset end time, the row is left open or in progress instead of closed.

## Limits

The data is synthetic, so it proves the pipeline works and shows the planted patterns. It does not prove Harborlight has the same patterns. Before trusting the same method on real data, the team would need to check category accuracy, missing resolution times, duplicate handling, time zone handling, and whether resolution time is being confused with agent handling time.

No real customer names or personal data are used.
